# 阶段 07 实施记录：覆盖聚类与UCB调度

## 做了什么

1. 从阶段 04 manifest 读取 4,525 个 eligible bins，从阶段 06 `bin_by_run.tsv` 读取 17 个真实初始向量，未引入旧 379-bin 项目。
2. 为每个 bin 生成 source component、scope、covergroup base、coverpoint/cross、bin kind、数值字面量/桶、normalized text 和结构标签；按 component + covergroup + point/cross 分区后执行确定性 Jaccard-token DBSCAN，并将超大簇稳定切分为最多 32 个 bin。
3. 按 rarity、uncertainty、diversity、size、structure 五项权重计算静态 cluster weight，并根据初始剩余机会生成 dynamic prior；输出 scheduler 输入，包含 17 个初始运行、实际命中 bin 列表和状态时间推导的 runtime。
4. 修正回放器后，用 32 submission、3 workers、seed 42 运行 replay-only 双层 UCB dry-run，按阶段 06 的墙钟区间设置虚拟完成时间，记录 policy/submit/complete 事件和哈希链；dry-run 不调用 VCS。

## 为什么这么做

所有算法输入必须来自新 schema，禁止混入旧 379-bin clusters。

## 为什么这么做

阶段 06 只提供 bin 命中矩阵，阶段 07 将它转成后续在线调度需要的 cluster、信息权重和可审计输入。先固定特征和分区，避免共享 package token 将不同 coverage domain 错误桥接；所有排序和 tie-break 都稳定化，便于跨机器复核。

## 怎么做

```powershell
python tools\cluster_stage07.py --manifest "06_初始语料与bin矩阵\evidence\public_20261101_initial\coverage_manifest.v1.json" --output "07_覆盖聚类与UCB调度\evidence\public_20261101_stage07\clusters"
python tools\score_stage07.py --clusters "07_覆盖聚类与UCB调度\evidence\public_20261101_stage07\clusters" --matrix "06_初始语料与bin矩阵\evidence\public_20261101_initial\bin_by_run.tsv" --status "06_初始语料与bin矩阵\evidence\public_20261101_initial\status.tsv" --test-pool "05_官方测试池与初始计划\evidence\2026-10-31\source_9f20940d_hashcomplete\test_pool.v1.json" --output "07_覆盖聚类与UCB调度\evidence\public_20261101_stage07\scores"
python tools\run_stage07_dryrun.py --inputs "07_覆盖聚类与UCB调度\evidence\public_20261101_stage07\scores\scheduler_inputs.json" --output "07_覆盖聚类与UCB调度\evidence\public_20261101_stage07\dryrun" --budget 32 --workers 3 --seed 42
```

实际运行使用本机 Python 3.12 标准库；输入/输出哈希和算法参数均写入公开 JSON。独立校验使用 `tools/verify_stage07.py`。

## 验收与局限

`verification.json` 为 `passed: true`：4,525 bins 唯一归属到 184 clusters，17 个初始运行和 376 个初始命中通过分数维度核验；修正后的 dry-run 产生 97 个带前序/自身 SHA-256 的事件，提交 32 次、完成 32 次、pending 为 0，没有启动新的 VCS run。最终覆盖仍为 376/4,525；虚拟 elapsed 1,553 秒仅是阶段 06 墙钟区间的 replay proxy。

cluster 参数、特征语义和 UCB 超参数是本项目为新 schema 选择的可审计工程定义，不是论文作者源码的已知复原。修正前回放器按 submission id 提前结束，遗留两个 pending；当前版本按虚拟 finish time 排序并排空 pending，同时纠正序列奖励只统计新覆盖 bins。runtime 来自阶段 06 status 的墙钟区间；dry-run 只回放已有向量，阶段 08 才会接入真实异步仿真反馈。
