## 为什么这么做

覆盖定义由源码 revision、DV 配置、工具和依赖共同决定。只记录 commit 名称不能证明服务器文件未被传输或行尾转换改写；因此本阶段同时校验 Git tree 和源文件字节。服务器没有可用包索引时，先在本机按 OpenTitan 锁文件校验下载，再离线传送，避免运行时依赖漂移或依赖服务器外网。

## 失败处理

1. **完整 tree 首次不符**：`dvsim.py` 的早期 help 探针产生两个 Python 字节码缓存，计数比归档多 2；删除新增缓存后重新计算，目标 tree 与 10,514 文件数通过。后续调用使用 `-B` 和 `PYTHONDONTWRITEBYTECODE=1`。
2. **首次 pip 安装缺 `wheel`**：源码发行包元数据阶段报 `invalid command 'bdist_wheel'`。新增 SHA-256 固定的 `wheel==0.45.1`，先离线安装后继续。
3. **FuseSoC 构建隔离**：FuseSoC 的上游 `setup.py` 声明 `setup_requires=setuptools_scm`；服务器尝试在线获取时 DNS 失败。固定并离线安装 `setuptools-scm==8.2.0` 和上游锁定的 `packaging==24.2` 后，安装完整通过。
4. **不覆盖既有目录**：源码完整树证据路径已经存在，所以验证器改为写入新的 `02_source_full_tree/`；离线 wheelhouse、构建工具目录和 venv 在创建前检查目标不存在。旧证据目录与阶段 01 环境均保留。

以上失败日志保留在服务器 `$ROOT/evidence/02_source/`，未发布到 Git，因为其中包含构建器临时路径。公开失败摘要及修复写在本记录中；公开可复核的最终机器证据放在 [evidence/public_20261031_01](evidence/public_20261031_01/)。
