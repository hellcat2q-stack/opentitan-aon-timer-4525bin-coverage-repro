## 为什么这么做

先用一个真实官方 test 验证 scheduler 选择、seed/test 元数据、VCS/URG 反馈和 4,525-bin 对齐，再决定是否扩大在线预算。每次任务使用新的 run ID 和独立源码副本，避免覆盖阶段 06 数据。

## 怎么做

服务器入口是 [`run_online_smoke.sh`](run_online_smoke.sh)，实际等价命令为：

```bash
bash "$ROOT/project/stage06/run_initial_corpus.sh" 20261101_online_01_aon_timer_sec_cm aon_timer_sec_cm
bash "$ROOT/project/stage06/extract_initial_vectors.sh" 20261101_online_01_aon_timer_sec_cm aon_timer_sec_cm
```

使用 OpenTitan revision `9f20940d494a223cc950a5b98f748fb28109d458`、VCS/URG P-2019.06-SP1、fixed seed 42、单 worker、`--cov`、`--no-rerun`。阶段 06 wrapper 在 per-run 副本中应用已记录的旧 VCS coverage 配置兼容补丁；锁定源码不变。

第二次 run 的实际命令为：

```bash
bash "$ROOT/project/stage08/run_online_smoke.sh" 20261101_online_02_aon_timer_sec_cm aon_timer_sec_cm
```

该 wrapper 最终调用阶段 06 的 `run_initial_corpus.sh` 与 `extract_initial_vectors.sh`。首次尝试因预先创建空 run 目录触发 wrapper 的 `RUN_EVIDENCE_ALREADY_EXISTS` 保护而未启动仿真；删除这个全新的空目录后重新启动，未修改任何既有 run。
