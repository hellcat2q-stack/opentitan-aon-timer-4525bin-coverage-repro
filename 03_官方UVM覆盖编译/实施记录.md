# 阶段 03 实施记录：官方UVM覆盖编译

**状态：已完成；执行日期：2026-10-31（北京时间）。** 最终运行 ID 为 `20261031_08`。服务器原始 VDB、simv 和 HTML 报告仍留在 `$HOME/opentitan_aon_timer_4525bin_repro`，仓库只保存脱敏证据。

## 做了什么

使用阶段 02 锁定的 OpenTitan revision 和独立依赖环境，在每次运行的临时源码副本中调用官方 `util/dvsim/dvsim.py`，选择 `aon_timer_smoke`、`aon_timer_smoke_vseq`、coverage build mode、fixed seed 42、单并发和不重试。最终运行依次完成 VCS build、UVM smoke、coverage merge 和 URG report。

最终结果是四个阶段均 `1/1` 通过；smoke 通过，`UVM_ERROR=0`、`UVM_FATAL=0`；URG 报告包含 1 个测试、16 个 group 条目和 4,525 个 group bins，并识别出官方 AON Timer 的 4 个 covergroups。单次 smoke 覆盖为 45/4,525，group score 0.99%。

## 为什么这么做

阶段 02 只证明源码、依赖和 Python CLI 可用，不能证明 VCS 能编译目标 DV、UVM sequence 会执行或 coverage 数据库有效。本阶段用官方 testbench、scoreboard、sequence 和 coverage 定义跑最小 smoke，并同时检查 VDB、URG 文本和 UVM 严重度，避免把“命令返回”误当作覆盖结果。

## 怎么做

服务器 wrapper：[`run_official_smoke.sh`](run_official_smoke.sh)。核心命令等价于：

```bash
<venv-opentitan-python> -B <revision-source>/util/dvsim/dvsim.py \
  <revision-source>/hw/ip/aon_timer/dv/aon_timer_sim_cfg.hjson \
  --proj-root <per-run-source-copy> --branch stage03 --local \
  --scratch-root <run-scratch>/dvsim --max-parallel 1 \
  --items aon_timer_smoke --cov --fixed-seed 42 --no-rerun \
  --max-odirs 1 --build-timeout-mins 120 --run-timeout-mins 30
```

服务器 VCS 为 P-2019.06-SP1。该版本不接受目标 revision 配置中的 `-cm_common_hier`，会把 `-xprop=mmsopt` 当作第二个 xprop 配置文件，也不接受新版 `cover.cfg+common_cov_excl.cfg` 层次配置写法。wrapper 只在临时副本中去掉前两个选项，并把两个层次配置按旧版 VCS 要求合并为一个文件；补丁前后哈希和原因见 [compatibility_patch.txt](evidence/public_20261031_02/compatibility_patch.txt)，锁定源码没有改动。

本机用 [`verify_stage03.py`](verify_stage03.py) 生成并复核公开证据。它检查四个 DVSim 阶段、UVM 错误/致命数、URG 报告、四个 AON Timer covergroup、输入哈希和私有路径脱敏。公开证据入口为 [evidence/public_20261031_02](evidence/public_20261031_02)。

## 失败处理

保留的早期 run 记录了真实兼容问题：`20261031_01` 在源码副本校验前发现锁定目录中残留 DVSim 生成的 `scratch/FUSESOC_IGNORE`；删除生成文件和空目录后 tree 恢复为 10,514 文件。`20261031_02` 首次构建找不到 FuseSoC，随后将 `.venv-opentitan/bin` 加入 wrapper 的 PATH。`20261031_03`、`20261031_04`、`20261031_05`、`20261031_07` 分别暴露旧 VCS 不支持的 coverage/xprop 参数、层次配置路径格式和配置顺序问题；每次均保留服务器日志并只修改临时副本，最终 `20261031_08` 通过。失败运行未被计入最终覆盖结果。
