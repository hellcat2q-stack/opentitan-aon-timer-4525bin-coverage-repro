# 阶段 04 实施记录：4525-bin 覆盖字典

**状态：已完成；执行日期：2026-10-31（北京时间）。**

## 做了什么

读取学校服务器阶段 03 run `20261031_08` 导出的完整 URG `groups.txt`/`grpinfo.txt`、`-group expand_bins` 展开报告和 cumulative/instance coverage XML，冻结 schema `opentitan-aon-timer-functional-4525-v1`。manifest 保存 4,533 条展开记录，其中 4,525 条参与实例计分，8 条 `weight=0` 作为元数据保留但排除出计分分母；同时保存每条记录的 covergroup、type/instance scope、coverpoint/cross、bin 名称、稳定 ID、权重、来源文件和行号。

## 为什么这么做

阶段 03 已证明官方 UVM、VCS coverage build、merge 和 URG 链路可运行，但仅有报告汇总行，不能直接支撑后续 bin-by-run 矩阵。阶段 04 把报告中的自动 bin 和 cross 明确展开，并把 URG 的两种口径分开：16 个 group 明细去重得到类型定义 4,507（46 命中），`instcov_for_score` 的实例计分分母为 4,525（45 命中）。这样后续阶段可以引用稳定 bin ID，不会把 4,507、4,525 和 AON 子集 4,279 混算。

## 怎么做

运行环境为本机 Python 3.12.14（只用标准库）；输入来自服务器 run `20261031_08`，源码 revision 为 `9f20940d494a223cc950a5b98f748fb28109d458`，工具为 VCS/URG P-2019.06-SP1。执行命令为：

```powershell
python "04_4525-bin覆盖字典/freeze_manifest.py" `
  --groups .stage_review/stage04_inputs/cov_report_groups.txt `
  --grpinfo .stage_review/stage04_inputs/cov_report_grpinfo.txt `
  --expanded-groups .stage_review/stage04_inputs/expand_groups.txt `
  --expanded-grpinfo .stage_review/stage04_inputs/expand_grpinfo.txt `
  --cumulative-xml .stage_review/stage04_inputs/cov_merge_testbench.cumulative.xml `
  --instance-xml .stage_review/stage04_inputs/cov_merge_testbench.inst.xml `
  --output-dir "04_4525-bin覆盖字典/evidence/2026-10-31/run_20261031_08" `
  --run-id 20261031_08
```

脚本不会覆盖已有输出目录。过程中修复了两项真实兼容问题：类型汇总不能误读 URG 的实例总计行；URG 对没有独立 instance detail 的 type-level group 使用 `Bins` 表，需按 COUNT 区分命中和未命中。`per_instance=1` 的 group 仍强制要求 XML 实例数和 URG 实例页面一致。

初次调用时 Windows 没有 `py` 启动器，随后改用本机 Python 3.12.14 运行。首次解析遇到上述两种 URG 口径/表格格式问题，修复后重新生成；失败运行未留下公开输出目录。

独立复核命令为：

```powershell
python "04_4525-bin覆盖字典/verify_stage04.py" `
  --bundle "04_4525-bin覆盖字典/evidence/2026-10-31/run_20261031_08"
```

复核结果为 `PASS`；同时检查 SHA256SUMS、manifest 哈希、公开文件中的 Windows/Unix 私有路径和核心计数。
